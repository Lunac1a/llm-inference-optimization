# 0.1.4：最小服务交付

本版围绕已验证的Qwen3-4B提供一条命令启动的mixed KV服务，不扩展模型兼容、不增加界面或模型下载管理器。

- `--model`接受原始本地权重目录；`doctor`检查固定运行库版本、模型结构、分片和tokenizer文件，不加载GPU模型。
- 默认mixed；启动成功显示API地址、模型别名和profile。启动失败输出明确错误或日志位置。
- 保留OpenAI兼容chat接口、SSE、模型列表、文档问答和健康检查。
- 默认最多8个活跃生成请求，流式连接也计入；超出返回429，结束或断开后释放名额。
- CLI对外绑定要求API key；自有后端仍只监听loopback。服务器部署继续使用同一命令。
- 默认推理参数和全部attention后端源码与0.1.3评测版本逐文件哈希一致。benchmark结论仍归属0.1.3，不扩写为新版本性能保证。

## 验证

- 源码服务回归20项通过，覆盖启动失败清理、认证、后端不可用、超时、SSE错误及并发名额释放。
- 独立wheel安装环境20项回归通过，CLI入口可用；该环境只安装API依赖，没有Torch/vLLM。包内17个源码/声明文件与工作区逐字节一致，包哈希记录于`.local/service-delivery-0.1.4/package.json`。
- 一次真实服务验收通过：约22秒启动、约24秒完成验收及退出。验证模型列表、错误key拒绝、普通chat、SSE结束标记，以及超过一个prefill chunk的文档问答；答案包含预期所有者Ada，日志确认`route=dual_source`与来源分支启用。
- 结束时API和后端端口均释放，无GPU compute进程残留。完整日志位于`.local/service-delivery-0.1.4/`。

这次真实验收是功能检查，未测生产吞吐、并发性能或长期稳定性。`doctor`不保证显存足够，也不验证本地权重与原始发布文件逐字节一致。安装和调用见[服务指南](serving.md)。
