# 研究范围：长上下文混合注意力

范围更新：2026-09-19。停止新增优化，整理最终 mixed 服务并扩大独立评测。

## 核心问题

在单卡、显存受限的 Qwen3/vLLM 环境中，研究历史 FP8 KV 与当前 BF16 K/V 的混合注意力，如何在长上下文输入、部分前缀命中和 Prefill/Decode 混合负载下改善执行效率，并控制回答质量、流式停顿和内存成本。

## 基础层

- 默认使用上游前缀缓存、连续批处理和分块 Prefill；文档内容放在变化的问题之前，以支持前缀复用。
- 当前默认 `chunked-hybrid` 提供 mixed 服务；`document` 是显式 BF16 对照，两者均开启前缀缓存与分块 Prefill。
- 基础能力属于实验基线。后续不把关闭缓存的弱基线作为混合注意力的主要收益来源。
- CPU KV 卸载、CUDA Graph 和预算预测不纳入默认基础层；相关代码与证据移入本地归档，活跃服务不再提供这些入口。

## 研究实现与贡献

- 当前候选：`chunked-hybrid`，历史 FP8 KV、当前 BF16 K/V、统一 softmax、查询块布局优化、已验证的单循环整块来源分支。
- 早期对照：`hybrid`，完整冷 Prefill 使用原始 BF16 Q/K/V，缓存路径使用上游 FP8 注意力。
- 项目贡献包括混合路径适配、双来源注意力扩展和查询块优化。vLLM 的调度、KV 管理、原生量化及被复用的注意力实现按上游贡献标注。
- API 是运行与端到端验证入口；预算预测、CPU 缓存恢复、文档管理产品功能和独立 Graph 优化不再作为并行研究方向。

## 比较规则

主要对照包括 BF16 注意力基线、原生 FP8 分块注意力、早期完整混合 Prefill 和当前分块混合注意力。缓存保持开启，以真实冷、热与部分命中状态区分工作负载。

不能直接用默认 profile 的不同资源限制归因注意力收益：`document` 为 32,768 上下文与自动分配 KV；当前候选为 16,640 上下文与固定 4 GiB KV。实验须固定模型、输入输出、并发和到达顺序、执行模式及资源预算。注意力路径比较固定分块大小；完整与分块 Prefill 的比较明确包含调度差异。比较 BF16/FP8 时说明是等字节内存预算还是等 token 容量。

数值检查以反量化历史 FP8 加当前 BF16 的 FP32 参考为准。它验证实现正确性，不替代与 BF16 基线的真实任务质量比较。

分别报告首字延迟、完成时间、流式内容块间隔、吞吐、KV 容量和回答质量。SSE 内容块间隔不称为精确 token 延迟。小规模测点不直接宣称生产 p95 或 SLA。

## 现有证据与后续边界

[查询块优化](attention-opt.md) 已有数值、微基准和两轮服务对照证据。相对早期完整 Prefill，当前候选减少流式停顿，但冷请求及混合批次完成仍更慢；研究目标允许明确的性能取舍。

后续实验只服务于混合注意力的正确性、性能归因与端到端有效性。每轮在执行前冻结具体假设、工作负载、资源额度、验收标准和停止条件。已验证的 mixed 实现按用户要求作为 0.1.3 默认服务；性能、质量结论仍限定于实际评测范围。

2026-09-18 已完成用户授权的首轮公开 RULER 评测，共 780 个正式响应。见 [质量与效率取舍](ruler-findings.md)：mixed 保留约 1.94 倍 KV token 容量，16K 请求总耗时比原生 FP8 少约 38%，但比 BF16 Flash 多约 29%；相对 BF16 的新增失分集中在 CWE 词频任务。该结果仅适用于本轮小样本、单并发冷输入。
