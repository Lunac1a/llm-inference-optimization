# Mixed 延迟初步诊断结果

2026-09-18。已完成独立诊断协议规定的四组、52 次请求和 4 份 CPU/CUDA trace，GPU 服务进程生命周期累计 **224.44 秒**，没有失败或重试。源码与产品默认设置未修改，端口 8032 已释放，结束检查没有 GPU compute 进程。

**初步结论：当前 16K 单请求的主要可优化区域是注意力 kernel。缓存量化写入、路由边界减法和可见 GPU 空隙均不是本轮的主要耗时。** 尚不能从 trace 判断注意力内部到底是历史读取、scale 读取、当前 BF16 读取、softmax 还是 tile 布局限制了性能。

## 协议与可复现范围

执行前冻结 [诊断协议](mixed-latency-protocol.md)。Qwen3-4B BF16、vLLM 0.23.0、Torch 2.11.0+cu130、RTX 4090 Laptop 16 GB。最大上下文 16640、分块 2048、4 GiB KV、NHD、eager、单请求并发；四组都使用相同参数，只改变目标后端/KV 路线。

输入为原 RULER `niah_single_1` sample 0，4K/8K/16K 实际分别为 **3960 / 8061 / 16245 tokens**。输出严格为 1 token，每次清空前缀缓存。各长度先热身一次，再按冻结顺序各测三次；最后单独采集一次 16K trace。测量阶段 profiler 未启动。所有请求均无前缀命中、无抢占，且完整收到结束标记。

这是热 kernel、冷 prefix、固定单输入的 Prefill + 首 token 诊断。没有检验多请求批处理、Decode、独立质量样本或候选优化的数值误差。本次没有优化候选，因此没有运行优化验收回归。

## 普通测量：首个非空 SSE 内容块到达时间

单位为秒，中位数（最小–最大）；每格 n=3。

| 路线 | 4K | 8K | 16K |
|---|---:|---:|---:|
| BF16 Flash | 0.532（0.530–0.549） | 1.248（1.242–1.271） | 3.222（3.172–3.318） |
| BF16 Triton | 0.587（0.564–0.588） | 1.536（1.525–1.559） | 4.302（3.974–4.326） |
| mixed Triton | 0.590（0.578–0.591） | 1.547（1.544–1.548） | 4.415（4.302–4.518） |
| 原生 FP8 Triton | 0.809（0.800–0.846） | 2.354（2.326–2.531） | 7.989（7.216–8.350） |

在这个固定负载上，mixed 的 16K 中位数比同后端 BF16 高约 **2.6%**，比 Flash 高约 **37.0%**，比原生 FP8 低约 **44.7%**。这些是描述性比例，不是性能等价、统计显著性或通用加速结论。三次样本存在随运行顺序增大的现象，尤其是原生 FP8；本轮未控制温度/频率，也未交错重启各组消除设备状态偏差。

本轮不能和历史 RULER 全任务延迟直接拼接：输入分布、输出长度、预热方式都不同。所有原始样本见 `analysis.json` 与各组 `results.jsonl`，追踪请求单列，不参与此表。

## 16K trace：GPU 实际 kernel 时间

下面按原始 `cat=kernel` 事件求和，排除包含这些 kernel 的 GPU annotation，避免重复计数。时间来自各组的一次追踪，不能当作无 profiler E2E 的严格分解。

| GPU 类别（毫秒） | BF16 Flash | BF16 Triton | mixed | 原生 FP8 |
|---|---:|---:|---:|---:|
| 注意力 | 1432.413 | 2312.916 | **2634.599** | 5946.345 |
| 矩阵乘法 | 1830.358 | 1817.548 | **1734.413** | 1957.811 |
| KV 写入（FP8 组含量化） | 8.297 | 6.764 | **10.452** | 11.976 |
| `aten::sub` 对应 GPU kernel | 0.009 | 0.009 | **0.365** | 0.009 |
| 其他 kernel | 120.619 | 119.382 | **115.482** | 122.555 |

mixed 的 kernel 总计 4495.312 毫秒，其中注意力约 **58.6%**，矩阵乘法约 **38.6%**，KV 写入约 **0.23%**。

利用 `External id` 将 GEMM 关联到 `aten::mm` 输入形状，mixed 的矩阵乘法可以进一步对应为：

| 运算 | 权重输入形状 | GPU 毫秒 | 次数 |
|---|---|---:|---:|
| QKV 投影 | 2560 × 6144 | 273.767 | 288 |
| Attention 输出投影 | 4096 × 2560 | 180.105 | 288 |
| MLP gate/up | 2560 × 19456 | 816.899 | 288 |
| MLP down | 9728 × 2560 | 450.660 | 288 |
| 词表投影 | 2560 × 151936 | 12.982 | 8 |

这些维度与当前模型 config 和已安装的 Qwen3 实现一致。36 层 × 8 个 Prefill 分块 = 288 次注意力。mixed 第一个无历史分块执行 36 次 `_fwd_kernel`（BF16，合计 27.468 毫秒）；后面七块执行 252 次 mixed `kernel_unified_attention`（合计 2607.132 毫秒），与预期路由相符。

mixed 各分块的注意力总时间依次为 **27.5、127.6、217.2、293.5、375.1、455.0、538.8、600.0 毫秒**。前七块各 2048 个新 token，最后一块 1909 个。历史增长时注意力耗时明显增加；该观察不能单独证明内存带宽受限。

## 路由、启动与空隙

- mixed 的 `aten::sub` 为 296 次，BF16 Triton 为 8 次，额外 288 次与每层、每 Prefill 分块的边界计算一致。mixed 所有减法的 GPU 时间仅 0.365 毫秒；CPU inclusive 时间为 8.175 毫秒。
- mixed 的 `aten::slice` 为 2375 次，BF16 Triton 为 935 次；CPU inclusive 时间分别为 5.971 / 2.096 毫秒。它们与其他 CPU 区间可能嵌套，不能相加成端到端成本。
- 从第一条到最后一条 GPU kernel/memcpy/memset 的时间包络内，mixed 未被这些 GPU 活动覆盖的区间合计 **13.741 毫秒**；BF16 Triton / FP8 / Flash 分别为 11.818 / 10.751 / 11.854 毫秒。此口径不包括首个 GPU 活动之前、最后一个活动之后的 HTTP/CPU 时间，也不能把全部空隙归因于 kernel 启动。
- mixed trace 记录到 profiler `Command Buffer Full` 开销，因此 CPU 细项和 GPU 区间只能用于定位，不作为无追踪精确延迟。普通测量与 trace 分开保存是必要的。

因此，本轮没有证据支持优先做逐序列边界处理优化。并发为 1，不能外推其在多序列批处理中的成本。

## 容量与实现归因

实际启动日志显示，在同一 4 GiB KV 字节预算下：BF16 两组容量均为 **29120 tokens**；mixed 与原生 FP8 均为 **56480 tokens**，约为 BF16 的 1.94 倍。本轮验证了配置下的已分配 token 容量，不代表并发压力验收。

已安装上游 unified attention 的 `BLOCK_M` 在此模型下为 **16**；本地 mixed Prefill 为 **64**。该模型 32 query heads / 8 KV heads，分别对应 `BLOCK_Q=4/16`。mixed 对原生 FP8 的差异同时包含无历史 BF16 路径、双源读取和 tile 布局，**不能把全部加速归因于使用当前 BF16 K/V**。缓存写入仍由上游完成。

## 下一步的单一候选方向

证据支持优先研究 **mixed 注意力的 query tile 布局**。如继续优化，首个候选可只改变 `PREFILL_BLOCK_M`（64 → 128），保持历史 FP8/当前 BF16、统一 softmax、分块与缓存容量不变；这是待验证假设，不是已证明更快的配置。本轮没有修改该值或追加调参。

执行该候选前另行冻结：同一混合精度数学参考的误差门槛、成对/交错延迟对照、实际容量检查，以及独立质量样本（重点 CWE）。若失败就保留现有实现。trace 没有硬件带宽/缓存命中率，也没有将 attention 内的各操作拆开；现有结果不足以接受优化或修改默认 baseline。
